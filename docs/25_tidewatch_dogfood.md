## 产品基线

海岛轻策略塔防：选择塔卡 → 点击固定建造位 → 自动攻击沿海岸路线来袭的敌人 → 获得贝壳、升级塔 → 波次间三选一 → 守住灯塔。

完整范围：6 关 × 5 波，3 类塔 × 3 级，4 类普通敌人、2 种 Boss、12 种局内升级，引导、选关、暂停、胜败结算、重开、声音开关、星级和本地存档。

第一可玩切片：1 关 5 波，3 塔、2 敌、建造/升级/出售、局内升级、胜败/重开全循环。切片不代表最终范围完成。

视觉基线：清爽 2D 海岛绘本，深蓝海水、奶油沙滩、珊瑚橙强调，真实 PNG 资产，清晰轮廓与交互状态。模型声称通过不等于验收通过。

## 实测发现与修复

### 1. 初始需求被误判成发布审批

复现：初始需求包含“不需要真实 AppID 或上线”“通过试玩验证”“未收到门禁二次确认不推进”。旧实现跨整段搜索“上线”和“通过”，立即生成“批准发布”评审，跳过正常专业对话。

修复：初始 idea 永不解析为门禁命令；普通群聊门禁识别改为独立的开头命令，而非跨句关键词组合。保留 UI 的“命令。解释”格式、二次确认、阶段约束与证据门禁。

验证：`npm run verify:gate-intent` 覆盖否定、条件、引用、问句、需求描述、明确 UI 命令；`npm run verify:room-gates` 验证现有门禁流程不回退。

### 2. 启动后等待从未提出的澄清问题

复现：启动创建任务时给策划/美术挂上“等待制作人回答”阻塞，同时关闭脚本回复和模型回复，界面停留空闲，制作人无法知道下一步。

修复：启动时请求真实角色模型完成澄清回复；不让初始 idea 执行审批协议。后续制作人回答照常唤醒任务。

验证：`npm run verify:project-kickoff` 用受控模型替身检查任务初始化、模型调用、回复交付和不误触发门禁。模型实际连接已分别在设置界面测试成功；游戏端到端结果另行记录。

- 对话明确区分讨论与写入任务，当前阶段的输入产物不再被提示为“通过该阶段后才生成”。

- 视觉模型分项分数由服务端计算总分；原始响应哈希保留，固定 rubric、阈值、语义绑定不放宽。
- Schema 错误返回具体字段、错误码和修复原因，避免只报“8 issues”导致模型盲猜。

### 制作人变更与审计闭环

- 显式 `change_request` 只选择明确点名角色/关联任务的当前阶段工作，取消旧执行代次，退回其依赖链；保留原始文件及证据，阻止旧产物继续作为当前输入。普通讨论/进度询问不触发回溯。受理后直接返回服务端回执并排程，不再等待一轮只读聊天。
- 审查 verdict=blocked 且有 requiredChanges 时同样向作者反馈；空闲名额滚动接续 DAG 下游，同角色最多一个并行任务。
- 自己的错误完成声明可以用严格第一行 `撤回声明：<claimId>` 纠正；不等于文件完成或门禁通过。审计区分生产任务、纠错任务、任务组，纠错完成必须有真实原作者撤回/补证记录。
- GameContract 终态允许明确启用的玩家输入退出到非终态（重试、选关），不再强制绕回全局菜单；仍拒绝后台 signal 自动退出和终态跳终态。
- 角色 @ 解析已抽离无副作用模块。回归测试曾因导入 `store.ts` 单例意外启动真实项目副本，已停止该测试及其子进程；恢复检查确认实际评审文件哈希仍与服务端 Ledger 一致。后续纯工具测试不再导入会自动恢复项目的模块。

### 从人工纠错转向 Agent 独立交付（09:28 起）

制作人明确纠正验收目标：不能由外部 Codex 逐项找出游戏问题并提供修法；要证明工作室的程序、QA 和其他专业角色能够自行发现、回派、修复、复测。此后没有由 Codex 修改游戏逻辑源码，群聊只发验收目标，不发新的具体游戏缺陷清单。

平台机制改进：

- `run_implementation_checks` 对真实源码树使用已安装 Creator 的 `cc.d.ts` 执行 TypeScript 语义检查，不再把 `transpileModule` 语法检查称为完整类型检查；缺少引擎类型时 blocked。并检查蓝图自定义组件注册、提示无纹理 Sprite 和初始视口外按钮。布局/纹理提示不是武断的运行失败结论，需 QA 核实。
- 程序新增服务端生成的 self-check 交付物；普通写入不能伪造，最终源码/蓝图哈希改变后失效。API 与 Claude MCP 共用验收逻辑。
- 新增构建前 QA 实现审查任务，不依赖成功构建或程序自检通过。输入包含 GDD、GameContract、Art Bible、蓝图、真实源码；构建必须同时消费程序自检和独立审查通过结果。
- 审查覆盖核心循环、数值成长、交互、视觉接入、存档、异常路径，逐项绑定基线和实现的精确原文。`submit_implementation_review` 使用专用字段 schema，检查结果由服务端填充。原文匹配证明有依据，但不等于模型的产品判断必然正确。
- 负面审查重开责任作者原任务，不让 QA 写游戏代码；返工要求放入可执行任务说明，不能放进阻塞数组导致修复任务自己无法调度。旧报告在源码树任何文件变化后失效，必须重新审查；真实 `run_playtest` 仍是后续独立门禁。
- Cocos 组件发现由单次正则匹配改为 TypeScript AST：支持一文件多组件、注册名与导出类名不同、默认导出，拒绝重复注册。生成的启动器用唯一导入别名，蓝图声明顺序决定同级渲染顺序，并转换 `Sprite.sizeMode` 枚举。
- `edit_code` 提供原文唯一匹配和全文件 hash 的精确修改，避免每次几行修复都重写大模块。`read_file` 返回完整文件 hash，即使只读取部分行。
- 实跑发现接入检查的预提交阶段误读正式工作区旧文件，修正为使用 staging 根目录。过期 self-check 不能通关，但不得因此丢弃有效源码修改。

- 任务级取消令牌与输入版本快照：上游产物版本/字节变化时取消旧快照任务，原 worker 退出后再释放角色槽位。旧结果不能写入群聊或触发虚假完成审计；无关角色继续工作。native staging 提交前再次验证输入版本。
